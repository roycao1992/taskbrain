# TaskBrain 数据存储说明

## 数据存在哪里

1. **云端（Supabase）**
   - 表：`user_data`，每个登录用户一行（`id` = 当前用户 UUID）
   - 字段：`tasks`、`profile`、`status`、`dark`、`notes`、`updated_at`
   - **同一账号在多台设备/浏览器上，以云端为准**（只要成功拉到云端数据就会用云端的覆盖本地）

2. **本地（浏览器 localStorage）**
   - 键名：`taskbrain-data`（所有账号共用同一个键，不按用户区分）
   - 内容：`{ tasks, profile, status, dark, notes }`
   - 作用：未登录时用这份数据；登录后也会把当前状态写回这里，作为缓存和离线时的后备

## 打开应用时数据怎么选

- **已登录**：先读本地，再请求云端。
  - **只要成功拿到云端这一行**：用云端数据覆盖界面，并随后写回 localStorage。
  - **拿不到云端（网络错误或该用户还没有行）**：用本地数据，并把这份数据上传到云端（相当于用本地覆盖云端一次）。

- **未登录**：只用本地 `taskbrain-data`；不请求、不写入云端。

## 为什么有时看到的数据和之前“不一样”

可能原因包括：

1. **多设备/多浏览器**
   - 云端是唯一真相源：最后在任意设备上保存的那份会覆盖其它设备下次打开时看到的。
   - 例如：在手机改完并同步后，再在电脑打开，会拉云端，看到的是手机那份；反之亦然。

2. **之前有一版逻辑不严谨**
   - 旧逻辑是“只有云端存在任务/分类/随笔时才用云端，否则用本地并上传”。
   - 若云端只有状态或档案、没有任务，会被误判为“云端没数据”，从而用本地覆盖云端，导致你感觉数据被换掉或丢了一部分。
   - 已改为：**只要成功取到云端这一行，就一律以云端为准**，避免误用本地覆盖云端。

3. **网络或 Supabase 异常**
   - 若某次打开时请求云端失败，会退回到本地缓存；若这份缓存是旧的或来自别的环境，就会看到“和之前不一样”的数据。

4. **localStorage 按域名/浏览器隔离**
   - 不同浏览器（或无痕模式）各有自己的 localStorage，彼此不同步，只有通过登录后的云端才会一致。

## 跨设备实时更新（Realtime）

- 登录后，应用会订阅当前用户在 Supabase 的 `user_data` 行变更。
- **在 A 地（如电脑）改完保存后，B 地（如手机）会自动收到更新并刷新列表**，无需手动刷新。
- 需在 Supabase 中开启该表的 Realtime：在 **SQL Editor** 执行 `supabase/migrations/003_realtime_user_data.sql` 中的语句（将 `user_data` 加入 `supabase_realtime` 发布）。若项目从未配置过 Realtime，可先在 Dashboard → Database → Realtime 中确认该表已启用。

## 建议

- 重要操作后稍等 1～2 秒再关页面，确保防抖保存（约 800ms）已把数据推到云端。
- 若发现数据不对，可先刷新一次，让应用重新从云端拉取；若仍异常，再检查网络和 Supabase 状态。
